### 0.5 How to read a case

Each case has: ID, source (first line), site, steps, expected result (exact texts are in quotes), level. Where it applies, there is also a blocker, a conflict, or a note.

- **Level** says where the check belongs best. **Manual** means a real wallet or a look-and-feel check that cannot be automated now. **E2E** means a browser test could do it later, or an existing E2E spec already covers it.
- **Source** says where the expected result comes from:
  - `dev QA note`: the "WHAT MUST HAPPEN NOW" text or a developer comment in the ticket.
  - `code`: read in the beta5 package. It confirms what was built, not what was asked.
  - `PO`: a product owner comment in PIWOO-944.
  - `Mollie docs`: Mollie's Express Component or Sessions documentation linked in the ticket.
  - `dev manual`: the developer's `manual-qa-8.2.0.md` (19 Oct), with its case number, for example `dev manual #8`. It describes the beta5 build and is newer than the ticket QA note.
  - `QA`: our own addition.
- **Conflict** means two sources disagree. Report it as an open question, not as a pass or fail.

### 0.6 Where to look during Express tests

- Orders: WooCommerce > Orders. Express orders have "Created via" `mollie_express` in the order meta.
- Logs: WooCommerce > Status > Logs, source `mollie-payments-for-woocommerce-`. Express events start with `express.` (for example `express.session.created`, `express.order.created`, `express.order.reused`, `express.payment.matched`, `express.abandoned.cancelled`). Warnings and errors are always logged. Info lines need the Mollie debug log setting on.
- Scheduled actions: WooCommerce > Status > Scheduled Actions, hook `mollie_woocommerce_cancel_unpaid_orders` (runs every 10 minutes).
- Browser devtools: Console for JS errors, Network for `wp-json/mollie/v1/express/session` and `wp-json/mollie/v1/express/order`.
- Mollie dashboard (live): payments and their status.

### 1.0 Release risk and open questions (read first)

- **Conflict, placement.** Dev QA note: the express area is at the top of the block checkout, with a grey shipping box. PO (13 Oct): for 8.2.0, Express must work as a regular payment method placed after address entry and shipping selection; the "true express" version at the top moves to the next release. Beta5 has the top version. Ask before release: is milestone 1 still planned for 8.2.0, and will a new beta follow? All cases below test what beta5 contains.
- **Conflict, address source.** Dev QA note: email and billing address come from the wallet, the shipping address comes from the checkout form. PO (21 Sep): data from the wallet takes precedence over stored data. The WIP PR #1324 comment says milestone 1 may need billing and email from the form. Not decided. Beta5 uses wallet data for billing, email and phone.
- **Conflict, shipping box.** Dev QA note (section 3): with items to ship and incomplete shipping details, a grey box "Express checkout" shows "Your order contains items to ship. Please fill in the shipping details to use express checkout." and "Waiting for the shipping cost…". Beta5 code: Express is loaded only when the price is final when the page is rendered. If shipping is not complete at page load, there is no express area at all and the old checkout buttons are shown instead. When shipping is complete, a line "Ships to <address> · <rate>" with a "Change" link is shown above the wallets. The grey box texts are no longer used. The developer's `manual-qa-8.2.0.md` (cases 6 to 8) confirms that this is the intended beta5 behaviour, including that a guest must reload after filling the address. So only the ticket QA note is out of date. Cases EXP-22 to EXP-26 test the beta5 behaviour. Ask the developer to update the ticket QA note.
- **New hiding rule not in the dev QA note.** When nothing ships, taxes are calculated on the customer address (WooCommerce "Calculate tax based on" = customer billing or shipping address), and the shopper has no saved country (guest, or new account), the express area is not shown (reason `tax_address_unknown`). See EXP-51.
- **Known open bug from the automated beta5 run:** on block checkout, the order note can say "Payment complete." instead of "Payment via <method> (tr_...)". Record the payment note text in every paid case.
- **Probable bug (PIWOO-856 rule):** the admin notice "Mollie express checkout: a payment was taken without an order" is printed as `notice notice-error` without the `data-mollie-error` mark (`src/ExpressComponent/WooCommerce/OrphanedExpressPayments.php:82`). Check it in EXP-47.
